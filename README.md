# KHYAL — خيال للأدوات المنزلية

واجهة أولية لمتجر عربي RTL متجاوب للموبايل والكمبيوتر، مبني باستخدام React + TypeScript + Vite، مع نقطة ربط Supabase.

> **حالة النسخة:** هذه نسخة MVP أولية. واجهة المتجر وسلة محلية ولوحة دخول وإضافة/تعديل/حذف المنتجات مبدئيًا موجودة. المنتجات التجريبية تظهر عند عدم إعداد Supabase. لا تعتبر النسخة متجرًا جاهزًا لاستقبال طلبات حقيقية قبل إكمال الاختبارات والإعدادات المذكورة أدناه.

## 1) تشغيل المشروع محليًا

يلزم كمبيوتر أو لابتوب لتشغيل أدوات التطوير بصورة أسهل. يمكن إدارة ملفات GitHub من الموبايل، لكن إنشاء المشروع وإصلاح الأخطاء عادة أسهل على الكمبيوتر.

1. ثبّت Node.js 20 أو أحدث وGit.
2. فك ضغط المشروع وافتح المجلد في Terminal.
3. نفّذ:

```bash
npm install
cp .env.example .env
npm run dev
```

افتح الرابط المحلي الذي يظهر في الطرفية.

## 2) إعداد Supabase

1. أنشئ مشروعًا في https://supabase.com/.
2. افتح SQL Editor وشغّل محتويات `supabase/schema.sql`.
3. من Project Settings / API انسخ Project URL ومفتاح publishable أو anon العام.
4. ضع القيم في ملف `.env`:

```env
VITE_SUPABASE_URL=https://YOUR_PROJECT_ID.supabase.co
VITE_SUPABASE_ANON_KEY=YOUR_PUBLIC_ANON_OR_PUBLISHABLE_KEY
VITE_WHATSAPP_NUMBER=201XXXXXXXXX
VITE_BASE_PATH=/
```

المفتاح العام فقط هو المسموح في واجهة المتصفح، مع تطبيق RLS. **لا تضع service_role key في `.env` للواجهة أو GitHub.** لا ترفع ملف `.env` إلى GitHub.

أعد تشغيل `npm run dev` بعد تغيير المتغيرات.

## 3) إنشاء حساب المدير الأول

1. في Supabase افتح Authentication ثم Users.
2. أنشئ المستخدم الأول ببريد إلكتروني تتحكم فيه وكلمة مرور قوية.
3. انسخ User ID الخاص به.
4. في SQL Editor نفّذ الاستعلام التالي بعد استبدال UUID:

```sql
insert into public.profiles (id, role)
values ('PASTE-USER-UUID-HERE', 'admin')
on conflict (id) do update set role = 'admin';
```

لا تفعّل التسجيل العام للمديرين. لا تعتمد على إخفاء عناصر لوحة التحكم فقط؛ صلاحيات قاعدة البيانات هي الأساس.

## 4) بيانات المنتجات

- عند عدم وجود إعدادات Supabase، تظهر منتجات تجريبية للعرض فقط.
- بعد إعداد Supabase، يقرأ المتجر المنتجات المنشورة من قاعدة البيانات.
- لوحة الإدارة تحتاج تسجيل دخول وحسابًا موجودًا في `profiles` بدور `admin`.
- هذه النسخة تستخدم روابط صور للمنتجات. دعم رفع الصور من داخل لوحة الإدارة يحتاج إضافة واجهة الرفع إلى Storage واختبارها قبل الاستخدام الفعلي.

## 5) النشر المجاني على GitHub Pages

1. أنشئ مستودع GitHub جديدًا باسم `khyal-store`.
2. ارفع الملفات إلى الفرع `main`.
3. افتح Settings → Secrets and variables → Actions → Variables وأضف:
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`
   - `VITE_WHATSAPP_NUMBER`
4. افتح Settings → Pages، واختر GitHub Actions كمصدر للنشر.
5. انتظر انتهاء الـ workflow من تبويب Actions.
6. افتح رابط Pages الذي يظهر في Settings → Pages.

ملف workflow يضبط المسار تلقائيًا لمستودع المشروع. لو غيرت اسم المستودع، أعد النشر. تأكد من أن مستودعك لا يحتوي على أسرار أو ملفات `.env`.

## 6) حدود النسخة الحالية — اقرأ قبل استقبال عملاء حقيقيين

- سلة التسوق الحالية محلية في المتصفح وليست محفوظة في حساب عميل.
- زر الطلب يجهز رسالة واتساب؛ لا يتم حفظ الطلبات في قاعدة البيانات بعد.
- لا توجد بوابة دفع إلكتروني.
- لوحة الإدارة الحالية تدير المنتجات فقط؛ إدارة الطلبات والتقارير وإعدادات المتجر تحتاج استكمالًا.
- رفع الصور من الداشبورد يحتاج استكمالًا؛ حاليًا يوجد حقل رابط الصورة.
- تأكد من تنفيذ سياسات RLS واختبارها من حساب زائر وحساب مدير قبل نشر بيانات حقيقية.
- لا تستخدم بيانات عملاء حقيقية قبل إضافة checkout آمن من جهة الخادم يتحقق من الأسعار والمخزون، مع rate limiting وحماية من الطلبات المزعجة.
- صور العرض قد تكون صورًا توضيحية من مصادر خارجية؛ استبدلها بصور تملك حق استخدامها. الأسعار والمنتجات التجريبية ليست عروضًا حقيقية.
- الخطة المجانية للخدمات قد تتغير وتخضع لحدود استخدام.

## 7) بناء نسخة الإنتاج واختبارها

```bash
npm run build
npm run preview
```

قبل الإعلان عن الموقع، اختبر على iOS Safari وAndroid Chrome وشاشات الكمبيوتر:
- البحث والأقسام والسلة.
- تسجيل دخول المدير والخروج.
- إضافة وتعديل وحذف المنتجات.
- عدم قدرة الزائر على تعديل المنتجات أو قراءة بيانات خاصة.
- صحة الروابط والصور ومقاسات الشاشة.
- أرقام واتساب، الأسعار، والمخزون.
